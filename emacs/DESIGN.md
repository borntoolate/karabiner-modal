# Emacs 版の設計判断と制約

Karabiner の設定ファイルそのものの仕組み（変数リーダー、`optional` 修飾キーの
素通し、2ストロークの状態機械、評価順など）は Vim 版の `../vim/ARCHITECTURE.md`
に書いてあります。**土台は完全に共通**なので、ここでは Emacs 版に固有の話だけ扱います。

---

## 1. なぜ「Caps Lock を本物の Control にする」方式にしなかったか

macOS はすでに Cocoa レベルで `C-a` `C-e` `C-f` `C-b` `C-n` `C-p` `C-d` `C-k` `C-y`
を標準搭載しています。だから「Caps Lock を Control にする」だけでも
それなりに Emacs 風にはなります。

それでもリーダー方式を採ったのは3つの理由からです。

**Vim 版と同じ土俵で比較するため。** どちらも Caps Lock 押下中だけ有効なので、
Karabiner の Enable を切り替えるだけで、同じ条件で試せます。
トリガーの押しやすさという変数が消えるので、割り当ての良し悪しだけを比べられます。

**macOS 標準の Emacs バインドを潰さないため。** リーダー方式なら、
本物の Control キーを使った `⌃A` `⌃E` などはそのまま生きています。
両方使えるので、移行中の保険になります。

**Cocoa を使っていないアプリでも動くため。** 標準のバインドは Cocoa の
テキストシステムに依存していますが、この設定は矢印キーなどの生のキーストロークを
送るので、より広い範囲で動きます。

---

## 2. なぜ Meta が Caps + Shift なのか

Emacs は**選択に Shift を使いません。** マーク（`C-SPC`）を置いてから移動すると、
その間が選択範囲になります。だから Shift が空いていて、Meta に回せます。

これは Vim 版との対比でも意味があります。

```
Vim 版：   Shift = 選択
Emacs 版： Shift = Meta（選択はマーク）
```

打鍵の物理面でも、Caps Lock と Shift は左端で縦に隣接しているので、
小指の腹で両方押さえられます。`Caps + ⌥ + f` は
ホーム段と最下段をまたぐ3キー同時押しになります。

### Option に変えたい場合

`gen.py` の `META_MOD` を `"option"` にして再生成してください。

```python
META_MOD = "option"
```

このとき Shift が空くので、**マーク方式と Shift 選択の両方**が使えるようになります。
マウスで選択した続きを `Caps + ⌥⇧F` の1手で伸ばせるのが利点です
（マーク方式だと `Caps + ⇧Space` → `Caps + ⇧F` の2手）。

なお **Option を Meta にしても他のアプリとの競合は増えません。** Option を読むのは
Caps Lock を押している間だけなので、`⌥F` で ƒ が入力されるのも、
`⌥⌘I` で開発者ツールが開くのも、そのままです。

## 3. マークの正体

この設定のマークは**本物の Emacs のマークではありません。**
`emacs_mark` という Karabiner の変数で、「以降の移動キーに Shift を自動で足す」
モードを表しているだけです。

```json
// マーク中の C-f
{ "from": { "key_code": "f", "modifiers": { "optional": ["caps_lock"] } },
  "to":   [ { "key_code": "right_arrow", "modifiers": ["left_shift"] } ],
  "conditions": [ emacs_mode == 1, emacs_mark == 1 ] }
```

つまりアプリから見れば、飛んでくるのはただの `⇧→` です。

### これによる利点

マーク位置を Karabiner が覚えているわけではなく、**アプリ自身が持っている
選択のアンカーがそのまま使われます。** そのため、マウスで選択した範囲の続きから
自然に伸ばせます。本物のマークだと「Karabiner が覚えている位置」と
「アプリが持っている選択」がずれてしまうので、むしろこの方式のほうが噛み合います。

Chromium で実測した結果です。

| 場面 | マウス選択 → `⇧→` | 結果 |
|---|---|---|
| 読み取り専用のページ | `"alpha "` → `"alpha bra"` | 伸びる |
| テキスト入力欄・`textarea` | `"lpha br"` → `"lpha brav"` | 伸びる |
| 選択が何もない読み取り専用ページ | `""` のまま | 効かない（キャレットがない） |

Safari（WebKit）は未検証です。同じ実装のはずですが断言はできません。

### これによる制約

- `C-x C-x`（point と mark の交換）は実装できません。位置を持っていないので。
- マークを置いた位置が視覚的に分かりません。移動を始めるまで選択は現れません。
- マークは Caps Lock を離すと消えます。押し直せば新しいマークになります。

## 4. kill ring がない

`C-k` `C-w` `M-w` `M-d` `M-DEL` はすべて **システムのクリップボード**（⌘X / ⌘C）を
経由します。本家の kill ring とは違い、`C-y` で取り出せるのは直前の1つだけです。
したがって `M-y`（yank-pop）は実装できません。

その代わり、**アプリをまたいで貼り付けられます。** 本家の kill ring は
Emacs の中に閉じているので、この点はむしろ macOS 版のほうが便利です。

### クリップボードを汚さずに消す

箱が1つしかないので、「貼り付けたい内容をコピー → 貼り付け先を `C-w` で消す → `C-y`」は
3手目でコピーを失って破綻します。逃げ道は**素の Delete キー**です。この設定が吸収するのは
⌥ だけで（§7）、修飾なしの Delete は素通りするため、マークで選んだ範囲がクリップボードに
触れずに消えます。マークは立ったままなので `C-g` か Caps Lock 解放で外してください。

Vim 版は同じ問題に別の答えを出していて、ビジュアルモードの `x` を
「クリップボードを汚さない削除」に割り当てています（Vim では `x` は `d` と同義なので、
あちらは意図的な逸脱）。Emacs 版で同じことをするなら `C-w` の意味を変えることになり、
kill ring の契約を崩すので採っていません。

### `C-k` の実装

```
⌘⇧→（行末まで選択） → ⌘X（切り取り）
```

行末にカーソルがある状態では選択範囲が空になるので、何も起きません。
本家の `C-k` は改行を削除して次の行と連結しますが、そこまでは再現していません。

## 5. 実装しなかったもの

| Emacs | 理由 |
|---|---|
| `C-l`（recenter-top-bottom） | 「カーソルを画面中央にスクロール」する相当機能が macOS にない |
| `C-t`（transpose-chars） | 汎用的に文字を入れ替える手段がない |
| `M-y`（yank-pop） | kill ring がなく、クリップボードは1つだけ |
| `C-u`（universal argument） | 数引数の概念を Karabiner に持ち込めない |
| `C-x C-x`（point と mark の交換） | マークが位置を持たないため |
| `C-x 2` `C-x 3` `C-x 1`（ウインドウ分割） | OS レベルの相当機能がない |
| `M-x`（コマンド実行） | 対応する概念がない |

### 近似で済ませたもの

| Emacs | 実装 | ずれ |
|---|---|---|
| `C-s` | ⌘F | 逐次検索ではなく、検索バーを開くだけ |
| `C-r` | ⌘⇧G | 検索を一度実行したあとでないと効かない |
| `M-a` / `M-e` | ⌥↑ / ⌥↓ | 文（sentence）単位ではなく段落単位。macOS に文単位の移動がない |
| `C-x o` | ⌘` | 「別ウインドウ」ではなく「同一アプリの次のウインドウ」 |
| `C-v` / `M-v` | Page Down / Page Up | アプリによってカーソルが動くものと動かないものがある |

## 6. `C-x C-c` について

`C-x` → `c` に ⌘Q を割り当ててあります。**アプリが終了します。**

Emacs としては正しいのですが、`C-x C-s`（保存）と隣り合っているうえ、
`s` と `c` はキーボード上でも近いので、誤爆の可能性があります。

外したい場合は `gen.py` の `X_COMMANDS` から
該当行を削除して再生成してください。

```python
X_COMMANDS = [
    ("s", "s", ["left_command"],               "C-x C-s: save"),
    ("f", "o", ["left_command"],               "C-x C-f: open file"),
    ("w", "s", ["left_command", "left_shift"], "C-x C-w: save as"),
    # ("c", "q", ["left_command"],             "C-x C-c: quit application"),  ← 削除
    ...
]
```

## 7. `⌥` は吸収し、`⌃` は素通りさせる

Caps Lock は修飾キーを出しません。変数を立てるだけです。そのため
**定義していない組み合わせはどのルールにもマッチせず、アプリに素通りします。**
素通りは「何も起きない」ではなく、macOS 側の割り当てが発火するという意味です。

ここで `⌥` と `⌃` の扱いが分かれます。

### `⌥` は吸収する

`META_MOD == "shift"` のとき、`⌥` にはこの設定上の意味がありません。
素通りすると US 配列では**文字入力**になります。

| 押すもの | 素通りすると |
|---|---|
| `⌥s` `⌥p` `⌥v` | ß、π、√ が入力される |
| `⌥e` `⌥i` `⌥u` `⌥n` | **アクセント記号を予約して、次の一打を食う** |

デッドキーが厄介です。画面上ほとんど変化がないまま次の打鍵が書き換わるので、
移動しているつもりで無言でアクセント付き文字が入り、原因も追えません。

`from.any` を使った1本のマニピュレータで、未定義の `⌥` を全部飲み込みます
（`META_MOD == "option"` のときは `⌥` が Meta なので生成しません）。

```json
{
  "type": "basic",
  "from": {
    "any": "key_code",
    "modifiers": { "mandatory": ["option"], "optional": ["caps_lock", "shift"] }
  },
  "to": [],
  "conditions": [ { "type": "variable_if", "name": "emacs_mode", "value": 1 } ]
}
```

`from.any` は全キーにマッチするので、**必ず最後に置きます。**

### `⌃` は素通りさせる — ここが Vim 版と逆

**macOS の `⌃` バインドは Emacs バインドそのものです。** `⌃a` が行頭、`⌃e` が行末、
`⌃y` が貼り付け、`⌃t` が文字の入れ替え、`⌃o` が行を開く。素通りしても、
この設定が同じキーに与えている意味と一致します。

```
Caps + a      →  ⌘←（この設定の C-a: 行頭）
Caps + ⌃ + a  →  素の ⌃a → macOS の C-a: 行頭        ← 同じ
Caps + ⌃ + y  →  素の ⌃y → yank                      ← Emacs の C-y と同じ
```

別の体系が顔を出しているのではなく、同じ体系の下地が見えているだけなので、
塞ぐ理由がありません。塞げば、いま機能しているものを無反応に変えるだけです。

**Vim 版では逆に `⌃` を吸収しています。** あちらでは2つの体系が食い違うためです
（`⌃v` は Vim では矩形ビジュアルですが macOS では1ページ下、`⌃o` は Vim では
ジャンプリストを戻りますが macOS では行を挿入します）。同じ「モードを閉じる」
という原則から、体系が一致するかどうかで逆の結論が出ています。

### `⌘` は両方とも素通りさせる

`⌘` はアプリのコマンド体系で、Emacs にも Vim にも `⌘` の記法はありません。
衝突しないので閉じません。吸収ルールの `mandatory` にも `optional` にも
`command` を書かないことが、そのまま除外になっています。`Caps + ⌘ + s` は保存のままです。

## 8. 評価順

Vim 版と同じく、Karabiner は manipulators を上から順に見て
最初にマッチしたものを採用します。この設定の並びは次のとおりです。

```
 0  リーダー（caps_lock）
 1  C-g（すべての状態をリセット）
 2-4 マークのトグル / 入力ソース切り替え
 5-12 C-x の2打目（emacs_x == 1。狭いので先）
13-26 マーク中の移動（emacs_mark == 1。Meta 版が先、Control 版が後）
27-36 Meta の編集・移動（mandatory shift）
37-55 Control の編集・移動
56  C-x の1打目（emacs_x != 1。いちばん広いので最後）
57  未定義の ⌥ を吸収（from.any。全キーを覆うので最後）
```

リポジトリのルートで `make check` を実行すると、
key_code の綴り間違いと、この順序のせいで到達不能になったルールを検出します。
`META_MOD` を `"option"` に切り替えた場合も含めて、検査を通ることを確認済みです。
